【本文件是「豆包每日自动签到」定时任务的完整指令, 由引导词在每次执行时读取】

任务: 向用户汇报豆包自动签到的结果。签到由系统级定时任务自动完成, 你不需要、也不允许执行任何脚本或命令——本任务只做「读取结果文件 + 汇报」。

0. 版本核对（先于一切）：本文件要求的引导词版本为 v1。检查你收到的任务指令（引导词）首行
   是否为「【引导词版本: v1】」。若没有该行、或版本不是 v1（说明引导词过期或被改过），汇报时
   必须把下面这段放在最开头并显著突出，然后再正常汇报签到结果：
   「⚠️ 签到任务需要更新：请打开豆包 → 左侧栏「定时任务」→ 找到本任务 → 编辑 →
   把仓库目录下 doubao-task-bootstrap.txt 的内容（首行版本标记保留，<仓库目录> 保持原路径）
   整段替换现有任务内容 → 保存。一分钟搞定，之后不会再打扰。」
   提示语必须原样传达以上操作步骤，不得省略或含糊。

1. 读取文件 <仓库目录>/data/last-result.json (即 引导词中给出的仓库目录下的 data/last-result.json)。
   这是系统定时任务每次签到后自动写入的只读结果文件, 内容不含任何凭据。
2. 把其中 report 字段的内容一句话汇报给用户, 并带上签到时间 (saved_at 字段)。
3. 如果 needs_attention 为 true, 按 result 字段补充提醒:
   - result 为 AUTH_ERROR 且 mode 为 client: 提醒用户「请打开豆包电脑版重新登录一次, 下轮自动恢复」。
   - result 为 AUTH_ERROR 且 mode 不是 client: 提醒用户「需要重新登录网页版签到通道 (运行 checkin.py login)」。
   - 其他异常: 把 screenshot 字段里的截图路径告诉用户。
4. 如果文件不存在, 或 saved_at 不是今天 (说明今天的签到还没跑完或系统任务异常), 汇报:
   「今天尚未检测到签到记录。系统定时任务会在稍后自动补签, 当天 24 点前补到都有效; 若整天都没有记录, 再叫我排查。」

注意:
- 本任务只读取上述文件做汇报; 不要执行任何脚本/命令、不要运行终端、不要修改任何文件。
- 任何情况下不得把「签到失败」说死——签到由系统级定时负责, 会自动重试与补签。

汇报格式 (严格遵守, 用户只想看结论):
- 第一句必须是给用户吃的定心丸, 二选一:
  - 读到今天的记录 → 「今日已签到 ✅」(附时间)。
  - 没读到今天的记录 → 「今天的签到会由系统定时自动完成并补跑, 无需处理 ✅」。
- 技术细节 (异常码、截图路径、设备在线与否等) 一律放在定心丸之后, 最多两三句; 如果对用户没有操作意义, 直接省略。
- 禁止把「设备不在线」「任务执行失败」「无法访问」这类过程性表述放在开头或单独成段——它们只是底层细节, 不是结论。
